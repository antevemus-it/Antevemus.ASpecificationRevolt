## [1.0.0] - 2026-10-20

The first release: the Revolt/Fibers satellite of `antevemus/aspecification` (ASpecification), milestone 15b of the ASpecification roadmap ("Fibers/Revolt adapter for non-HTTP sources"). It requires ASpecification **2.6.0** (`^2.6`), the release that added the hook it plugs into: `IDeferredDataSource` (a source fetched by a stage transport) and `IStageTransport` (`fetchAll()` of every pending request of that transport in a stage), with the three groups of a resolution stage (the HTTP batch, then one `fetchAll()` per transport, then the other sources).

### Added

- **`RevoltDataSource`** (final, implements `IDeferredDataSource`): `new RevoltDataSource(Closure $fetch, int $cost = 0, ?int $ttl = null, float $timeout = 5.0, ?RevoltStageTransport $transport = null)`. The closure receives the parameters of the request and the `DataRequest` by the arity rule of `CallableDataSource` (`fn(array $p)` works), and, when it declares a third parameter (or is variadic), the request's `Amp\Cancellation`; it runs in a Fiber under the event loop, may suspend, and may return a value or an `Amp\Future` (awaited with the same cancellation). A negative TTL and a timeout that is not a positive finite number are refused (`InvalidArgumentException`). `getTransport()` returns the transport given or `RevoltStageTransport::shared()`; `getCost()`, `getTtl()`, `getTimeout()`. `fetch()` is the synchronous path outside a resolution scope: one request through the source's transport, its value returned or its failure thrown.
- **`RevoltStageTransport`** (final, implements `IStageTransport`): `new RevoltStageTransport(int $maxConcurrency = 8)` (below 1 refused), `shared()` (one process-wide instance, created on first use), `getMaxConcurrency()`. `fetchAll()` starts one Fiber per request through its `RevoltRunner`, at most `maxConcurrency` at a time (the others wait for a slot in key order, each in a Fiber of its own, so waiting never outlasts the deadline), each with its source's `timeout`, and, with a deadline, one `Amp\TimeoutCancellation` of the time left shared by every request of the call: the unfinished requests are cancelled at the deadline and the call returns then. It answers by key: the value, or the failure.
- **The failures of the core's own sources**: an exception of the closure becomes `DataFetchException::sourceFailed()` (the original as previous), as for a `CallableDataSource`; a `DataPendingException` passes through as it is, so the request is listed by `ResolvedData::getPendingRequests()` and `SpecificationResult::isPending()` answers true; the source's own time limit is `DataFetchException::timeout()`, as for an `HttpDataSource`; the resolution deadline is `DataFetchException::resolutionTimeout()`. With less time left than the core's minimum budget (`CurlMultiTransport::MIN_START_BUDGET`, 10 ms), nothing is started and every request fails with `resolutionTimeout()`, as the core's `curl_multi` batch does. Messages carry the source name and the class of the original only, never a parameter value.
- **Another `IDeferredDataSource`** that names a `RevoltStageTransport` is fetched through its own `fetch()` inside a Fiber, its exception kept as it is, the deadline applied.
- **The event loop**: the application's `Revolt\EventLoop`, never a driver of its own. Outside a Fiber the wait runs the loop; inside one (an Amp server, `Amp\async()`) it suspends only that Fiber. One transport caps every call through it together, concurrent resolutions in different Fibers included.
- **`RevoltRunner`** (final): a copy of the runner of `antevemus/alinq-revolt` 1.0.0 (same author, only the namespace changed), kept as a copy so neither satellite depends on the other.
- **Documentation** in `docs/en` and `docs/pt-BR` (Docs Kit format): Getting started, How it works, RevoltDataSource and the transport, Tests, Roadmap; the README of each language is an index whose only code is the Quick Start. Every one of the 7 PHP blocks per language is run by `DocumentationBlocksTest` with its written answers, and `DocumentationTreeTest` keeps the two trees aligned.
- **CI**: `tests.yml` (PHP 8.2, 8.3 and 8.4, `composer validate --strict`, PHPUnit) and `quality.yml` (Infection over the whole `src/`, with a minimum MSI).

### Notes

- **Suite**: 85 tests and 4974 assertions, none skipped (PHP 8.4.13, against ASpecification 2.6.0; the same suite passes on PHP 8.2.34): `RevoltStageTransportTest` 20 tests / 136 assertions, `RevoltDataSourceTest` 13 / 46, `RevoltRunnerTest` 16 / 50, `ParityTest` 2 / 161, `ResolutionPropertyTest` 1 / 3935 (300 seeded cases), `HttpParityTest` 2 / 61 and `ProofOfGainTest` 6 / 19 (group `http`, a local Amp server, about 11 s), `DocumentationBlocksTest` 17 / 127 (the 7 blocks of each language and the Quick Start of each README), `DocumentationTreeTest` 8 / 439.
- **Parity of answers**: the same trees over the same battery give the same verdicts, evaluation errors, `evaluation_error` flags, reasons, codes, exception classes and source names, failed requests and stage and fetch counts through `CallableDataSource` and `RevoltDataSource` (150 comparisons, three policies) and through `HttpDataSource`, `RevoltDataSource` with the Amp HTTP client and `CallableDataSource` against a local server (52 comparisons; a status outside 2xx is `httpStatus()` for the HTTP source and `sourceFailed()` for the closures, whose client raised on it).
- **Mutation testing**: Infection 0.35.8 over the whole `src/` (PHP 8.4.13, pcov, the group `http` left out): 121 mutants, 115 killed, 2 errors (detected), 4 escaped, all equivalent (in `RevoltRunner` the same three as in `antevemus/alinq-revolt`; in `RevoltStageTransport` a `<` turned into `<=` between two readings of a monotonic clock); MSI 96.69%. `minMsi`/`minCoveredMsi` 95.
- **Measured gain** (`XDEBUG_MODE=off php tests/Support/timing-table.php 3`, median of 3 runs, PHP 8.4.13, a local Amp HTTP server answering in 200 ms): one resolution of 16 sources takes 3 227 ms as `CallableDataSource` with a blocking client, 428 ms as `RevoltDataSource` with the Amp HTTP client and the default `maxConcurrency` 8, 215 ms with 16, 210 ms through the core's `HttpDataSource` batch, and 3 244 ms as `RevoltDataSource` with the blocking client. Eight closures that only compute take as long either way. The full table: `docs/en/quality/tests.md`.
- **Development dependency**: `infection/infection` is `^0.31.9 || ^0.35.6`, as in the core: 0.35 requires PHP 8.3, and the CI leg of PHP 8.2 installs 0.31.
